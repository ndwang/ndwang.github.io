Early coding workflow vs native tool calling

Before agents could write files directly, developers copy-pasted code by hand. Aider's SEARCH/REPLACE automated the edit — but parsing text is fragile. Native tool calls made file edits a first-class, schema-validated operation.

Before coding agents, ChatGPT was a smart autocomplete — it answered questions about code but had no awareness of your files. The developer had to describe the problem from memory, read the response, click Copy, switch to the editor, find the right file and line, paste the code, fix any formatting issues, and save. The model was never involved in applying the change.

Aider was a genuine breakthrough: it copied file content into the prompt so the model could see the actual code, then applied the SEARCH/REPLACE edit automatically — no human copy-paste needed. But both halves had friction. Reading files meant injecting their full text upfront. Applying edits required exact string matching; whitespace drift or a partial line triggered an error and a retry loop — the model re-prompted up to three times before aborting. When the model was precise it worked smoothly; when it wasn't, the session stalled.

With native tool calling the model isn't limited to files you explicitly hand it. Given a vague description — "login is broken" — it can list a directory, read the likely candidates, reason about what changed across the refactor, and make targeted edits across multiple files. The developer never named a file or a line. With Aider's approach you had to know which file to add to the session first. Here the model does the investigation itself, using tools the same way a developer would search their own codebase.
