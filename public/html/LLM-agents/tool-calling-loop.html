The LLM tool-calling loop

The atomic unit of every LLM agent — click through each stage.

Step 1 of 5

This four-stage cycle is the atomic unit of every LLM agent. The model never touches tools directly — the harness sits between, parsing output and feeding results back into the conversation. Click a stage or use Next to walk through it step by step.

When the model needs information it doesn't have, it doesn't guess — it emits a structured JSON object naming the tool and its arguments. Then it stops. The model has no idea yet what the answer is; it's delegating to the outside world.

The harness is the invisible orchestrator. It reads the model's output, recognises a tool call, looks up which function to run, and manages everything that can go wrong — timeouts, malformed results, retries. In 2023, early frameworks like LangChain were almost entirely harness code compensating for models that couldn't do this reliably on their own.

The tool runs — it might search the web, query a database, call an API, run code, or read a file. It returns a plain string back to the harness. The tool itself is just a function; it has no knowledge of the model, the user, or the conversation. It just does one thing and returns a result.

The harness appends the tool result to the conversation history, then sends the whole thing — user message, tool call, and result — back to the model. The model now has what it needed and generates the final answer. If it needs more tools, the loop starts again. There is no limit to how many times it can repeat.
